# MusicPlayer 项目介绍书

## 项目简介

MusicPlayer 是一个前后端分离的 Android 音乐播放器项目，整体由 Android 客户端和 Node.js 后端两部分组成。项目围绕“在线播放 + 本地管理 + 用户体系 + 歌词体验”展开，实现了在线歌曲浏览、搜索、播放、下载、收藏、最近播放、用户登录注册、资料管理、版本更新等完整能力。

当前版本为 `v2.0`，Android 端最低支持 `Android 12`，采用 `Java 11` 开发；后端基于 `Node.js + Express + MySQL` 实现，为客户端提供歌曲数据、音频播放流、用户接口和版本更新接口。

## 项目定位

本项目定位为一个具备完整业务闭环的音乐播放器应用，而不是单一的播放 Demo。它既覆盖了播放器基础能力，也包含了实际产品中常见的账号系统、缓存机制、后台播放、歌词同步、下载管理和版本更新能力，适合作为 Android 综合项目、课程设计、毕业设计或作品集项目进行展示。

## 核心功能

- 在线音乐播放：支持从服务端拉取歌曲列表并在线播放。
- 本地音乐管理：支持导入本地音频文件，并纳入本地曲库管理。
- 搜索功能：支持按歌曲名、歌手、专辑进行检索。
- 歌词同步：支持在线获取歌词、LRC 解析、播放进度同步展示。
- 下载功能：支持歌曲下载到本地，并显示下载进度。
- 收藏与最近播放：支持收藏歌曲、记录最近播放列表与播放统计。
- 用户系统：支持注册、登录、资料查询、资料修改、密码修改与账号注销。
- 后台播放：支持通知栏控制、音频焦点管理、耳机拔出自动暂停。
- 应用更新：支持版本检测、更新日志展示与 APK 下载安装。
- 主题支持：支持浅色、深色和跟随系统的主题模式。

## 技术架构

### 整体架构

项目采用前后端分离设计：

- Android 客户端负责界面渲染、用户交互、播放控制、本地缓存、歌词展示、下载与用户操作。
- Node.js 后端负责歌曲数据服务、音频流分发、用户认证、资料管理和版本更新接口。
- MySQL 用于持久化歌曲、用户、版本等服务端数据。
- Room 数据库用于 Android 端本地缓存歌曲、歌词、收藏状态、最近播放等信息。

### Android 端架构

Android 端采用 `单 Activity + 多 Fragment + MVVM` 架构：

- `MainActivity` 作为唯一主界面容器，负责底部导航、迷你播放器、Fragment 切换、播放器控制器绑定和全局交互协调。
- `MainViewModel` 作为状态中心，统一管理歌曲列表、当前播放歌曲、播放进度、歌词、循环模式、用户资料和同步状态。
- `PlaybackService` 基于 Media3 `MediaSessionService` 实现后台播放能力，内部封装 ExoPlayer，并提供通知栏控制。
- 各业务页面通过 Fragment 拆分，包括发现页、全屏播放器、个人中心、收藏列表、本地音乐、最近播放、设置页、资料编辑等。

### 数据流设计

项目采用“远程数据 + 本地缓存”双层模式：

1. 应用启动后先从 Room 读取本地歌曲并显示，降低白屏时间。
2. 随后后台请求服务端歌曲列表，将远程数据同步到本地数据库。
3. 同步时保留本地收藏、下载路径和本地导入状态，避免远程覆盖本地状态。
4. 界面通过 LiveData 观察数据库或 ViewModel 状态变化，自动刷新 UI。

这种设计兼顾了启动速度、离线体验和数据一致性。

## 主要模块说明

### 1. 主界面模块

主界面由 `MainActivity` 承担，负责：

- 检查登录状态，未登录时跳转登录页。
- 初始化主题、歌词服务、媒体控制器和底部导航。
- 加载发现页、个人中心页和播放器页。
- 维护迷你播放器与播放进度显示。

### 2. 播放模块

播放能力由 `PlaybackService + MediaController + ExoPlayer` 共同实现：

- `PlaybackService` 常驻后台，持有 ExoPlayer 实例。
- `MainActivity` 通过 `MediaController` 连接服务并发出控制命令。
- 支持播放、暂停、上一首、下一首、拖动进度、单曲循环、列表循环。
- 支持系统通知栏控制和后台持续播放。

这种实现方式将播放生命周期从界面中解耦，使应用切换页面或进入后台后仍能持续播放音乐。

### 3. 歌词模块

歌词能力由 `LrcLibService` 和 `LyricUtils` 实现：

- 优先读取本地缓存歌词。
- 当本地无歌词时，向 LRCLIB 接口发起歌词检索。
- 支持通过 `lrcId` 精确获取歌词，也支持按歌曲名、歌手、专辑、时长模糊检索。
- 将 LRC 内容解析为时间轴结构，并随播放进度动态定位当前歌词。

为降低重复请求，歌词模块还实现了内存缓存、持久缓存和并发请求合并。

### 4. 下载与本地音乐模块

下载功能由 `DownloadManager` 实现：

- 基于 OkHttp 下载音频文件。
- 将文件保存到应用外部音乐目录。
- 通过通知栏显示下载进度。
- 下载成功后自动更新数据库，将歌曲标记为本地文件。

本地音乐部分支持两种来源：

- 在线歌曲下载后的本地化管理。
- 用户手动导入本地音频文件。

系统会区分“下载音乐”和“导入音乐”，方便在个人中心分组查看。

### 5. 用户系统模块

用户能力由 `UserManager` 与后端 JWT 接口共同实现：

- 支持注册与登录。
- 登录成功后本地保存 Token 和用户信息。
- 支持获取资料、编辑资料、上传头像、修改密码与注销账号。
- 应用启动时根据登录状态决定是否进入主界面。

### 6. 更新模块

更新能力由 `UpdateManager` 实现：

- 启动时自动检查版本。
- 可在设置页手动检测更新。
- 服务端返回版本号、下载地址和更新日志。
- 客户端支持下载 APK 并触发安装流程。

## 后端实现

后端采用 `Express + MySQL` 构建 REST API 服务，默认端口为 `3000`。核心职责包括：

- 提供歌曲分页列表与全量列表接口。
- 提供歌曲搜索接口。
- 提供歌曲播放接口。
- 提供用户注册、登录、资料管理接口。
- 提供版本检查接口。
- 提供静态资源访问能力。

其中，`/api/song/play` 接口支持 `HTTP Range`，可以让客户端按需分段拉取音频数据，满足在线播放、拖动进度和断点续传等需求。

## 技术栈

### Android 客户端

- 语言：Java 11
- 架构：MVVM
- UI：Activity + Fragment
- 播放：AndroidX Media3、ExoPlayer
- 数据库：Room
- 网络：OkHttp、Gson
- 图片加载：Coil
- 主题与界面增强：Palette、Lottie
- 并发：ExecutorService、Handler、LiveData

### 后端服务

- 运行环境：Node.js
- 框架：Express
- 数据库：MySQL
- 鉴权：JWT
- 密码加密：bcryptjs

## 运行方式

### Android 客户端

在项目根目录执行：

```bash
./gradlew assembleDebug
```

如需构建发布包：

```bash
./gradlew assembleRelease
```

Windows 环境也可以使用：

```bash
gradlew.bat assembleDebug
gradlew.bat assembleRelease
```

### Node.js 后端

进入 `web` 目录后安装依赖并启动：

```bash
cd web
npm install
npm install bcryptjs jsonwebtoken
npm start
```

开发模式可使用：

```bash
npm run dev
```
